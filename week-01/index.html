01 / Algorithms

What is an algorithm?

An algorithm is a precise sequence of steps for solving a problem. For the problems in this lesson, it must finish and produce the intended result for valid inputs.

Precise

Each instruction has a clear meaning. “Move one cell east” can be executed; “go somewhere near the goal” needs clarification.

Ordered & finite

The order matters, and the process must stop. A finite description alone does not guarantee that its execution will finish.

Correct

The steps must meet the problem’s requirements for every allowed input. Finishing with the wrong result is still a failure.

Algorithm and program

The algorithm describes the solution. A program expresses those steps in a language a computer can execute. One algorithm can be implemented in many languages.

03 / Pseudocode

Sequence, variables & pseudocode.

Pseudocode is a readable description of an algorithm. It has no single universal syntax; we will use a small, consistent notation throughout the course.

Our notation

  • INPUT receives a value.
  • OUTPUT displays a result.
  • ← assigns a value to a variable.
  • IF / ELSE / END IF describes a decision.

What is a variable?

A variable is a name associated with a value. In these examples, a memory table shows the current value for each name.

total ← a + b means: evaluate the expression on the right, then associate the result with total.

    05 / Testing and debugging

    Tracing, testing, and debugging

    Tracing follows execution step by step. Testing compares an actual result with an expected result. Debugging finds and fixes the cause of a mismatch.

    Trace the state

    Record which instruction runs and how variable values change. A trace table helps you explain an unexpected output.

    Choose useful inputs

    Cover both branches, equal inputs, and allowed values such as zero and negative numbers.

    Compare with the requirement

    Work out the expected result independently. Passing a few examples provides evidence; it does not prove correctness for every input.

    Practice / Can your tests expose the bug?

    Expected vs actual

    This version compares a ≥ b, but its outputs may be connected to the wrong branches. Choose a version, predict which tests fail, then run the cases.

    IF a ≥ b THEN
    OUTPUT b
ELSE
    OUTPUT a
END IF
    Find a counterexample.

    One input with a wrong result is enough to show the algorithm is incorrect. Equal values can hide this particular bug.

    Test cases for the larger-number problem
    CaseabExpectedActualResult
    Test the algorithm against the requirement: output the larger value.
    Three kinds of mistakes you will meet in Python
    • Syntax error: the code breaks the language’s grammar, such as a missing colon.
    • Runtime error: execution encounters a problem, such as dividing by zero.
    • Logic error: the code runs, but its result does not meet the requirement.

    Swapping the branch outputs is a logic error.

    06 / Python history

    A short story of Python.

    Python began as Guido van Rossum’s project to create an extensible scripting language. Its readable style makes our algorithms easy to express.

    Explore / Three moments in the story

    Click a moment

    1989 / The first implementation

    During the Christmas holidays, Guido van Rossum began implementing Python while working at CWI in the Netherlands. His experience with ABC influenced features such as indentation for grouping statements.

    History source: Python’s official FAQ.

    What kind of language is it?

    High level

    Write expressions and instructions using names and familiar operations. Python handles many lower-level details.

    General purpose

    Python supports tasks such as automation, web development, scientific computing, and data analysis.

    Interpreted

    You can enter instructions in a Python shell or run a saved script with a Python interpreter. The interpreter executes your program.

    Our course uses Python 3.

    A .py file is a text file containing Python source code. The >>> you may see in the interactive shell is a prompt, not something to copy into a script.

    Names & case matter

    Use descriptive names such as total or student_name. Names can contain letters, digits, and underscores, but cannot start with a digit or be a keyword.

    score and Score are different names. Python keywords such as if use their exact spelling.

    score == 10 asks whether the values are equal. Comparisons produce True or False.

    08 / Input and output

    From input to output.

    Our sum algorithm becomes a Python program with the same sequence of steps. One new detail matters: keyboard input arrives as text.

    The plan / Pseudocode

    INPUT a
INPUT b
total ← a + b
OUTPUT total

    The program / Python

    a = int(input("First number: "))
b = int(input("Second number: "))
total = a + b
print(total)
    Read the nested calls from inside out.

    input() displays a prompt and returns the typed text as a str. int() converts valid integer text into an int. Then = assigns that integer to a name.

    What if the input is not an integer?

    int("hello") and int("3.5") raise a ValueError. The example assumes valid integer input. Handling invalid input is a later topic.

    Decimal values use float(), for example float("3.5"). Use one type consistently with the problem’s requirements.
